# 用户旅程与原子故事分解 —— 智能企业文档管理平台（DocHub）

> 文档版本：v1.0
> 产品定位：面向中小企业的“管理 + 智能”双引擎智能文档管理平台
> 文档目标：梳理三种角色的端到端用户旅程，并提炼符合 INVEST 原则的核心原子化用户故事，作为后续需求拆解与迭代排期的基础。

---

## 1. 产品概览与设计约束

DocHub 采用 **“管理层 + 智能层”双引擎**架构，服务中小企业级文档的安全存储、版本管理与协作流转，并借助 AI 实现“查看 → 检索 → 合成”的文档增值闭环。

### 1.1 双引擎说明

- **管理层**：部门化权限体系（部门空间 + 角色权限：查看者 / 编辑者 / 管理员），支撑文档安全存储、版本管理与协作流转。
- **智能层**：以“查看 → 检索 → 合成”三步闭环为核心，支持语义检索，并基于已有文档自动合成**带引用溯源的新文档**（如周报汇总、方案初稿、制度摘要）。

### 1.2 角色定义

| 角色 | 定位 | 核心关切 |
| --- | --- | --- |
| 普通员工 | 日常文档的生产者与使用者 | 高效上传 / 查看 / 检索 / 合成 / 归档 |
| 部门文档管理员 | 部门空间的治理者 | 权限分配、空间管理、文档治理 |
| 超级管理员（IT/行政） | 系统级负责人 | 系统配置、存储配额、安全审计 |

### 1.3 MVP 极简边界（本版本明确不做的内容）

为遵循 **MVP 极简闭环原则**，以下能力本版本**明确暂不引入**，以避免过度设计、控制交付复杂度：

- ❌ 全文搜索引擎（自建索引 / Elasticsearch 等）
- ❌ 在线多人实时协同编辑（类似 Google Docs 的 OT / CRDT 能力）
- ❌ 文档审批流
- ❌ 跨组织外部分享

同时，**必须保留**的智能层底线要求：AI 合成结果**必须支持来源标注**，且**需经人工确认后方可入库归档**。

## 2. 端到端用户旅程地图（User Journey）

### 2.1 普通员工 —— 完整文档管理闭环

旅程主线：**上传 / 查看文档 → 检索文档 → 基于检索结果合成新文档 → 归档沉淀**。

| 阶段 | 用户行为 | 系统 / 平台功能 | 用户目标 | 情绪 / 痛点 |
| --- | --- | --- | --- | --- |
| **① 上传 / 查看** | 进入部门空间，查看已有文档；上传新文档或在线预览 | 文档列表、上传入库、在线预览、版本记录 | 快速找到所需文档，并把自己的文档安全入库 | 目录混乱、找不到入口；格式不支持预览 |
| **② 检索** | 输入自然语言问题，基于全文 / 语义检索定位相关文档 | 语义检索、结果列表、引用来源展示 | 用最少操作精确命中相关文档 | 关键词不精确导致检索失效 |
| **③ 合成** | 选定检索结果，发起 AI 合成（周报汇总 / 方案初稿 / 制度摘要等） | AI 合成、来源标注、生成中进度提示 | 从分散文档中快速生成结构化的新内容 | 生成耗时、不确定来源、结果不可控 |
| **④ 结果确认** | 审阅 AI 合成结果与引用来源，编辑修正 | 来源标注、在线编辑（单用户）、人工确认 | 产出可信、可追溯的内容 | 引用错误、来源不透明 |
| **⑤ 归档沉淀** | 将确认后的新文档保存入库并归档至指定目录 | 入库归档、权限继承、版本与历史 | 让产出持久沉淀、他人可复用 | 不敢误存、目录不清 |

**普通员工旅程要点**
- 全程在**部门空间**内进行，可见范围受角色权限约束。
- “查看 → 检索 → 合成 → 确认 → 归档”构成一个可重复的闭环，合成结果并非即刻入库，而是**先人工确认、后归档**，确保质量与溯源。

---

### 2.2 部门文档管理员 —— 权限分配与文档治理

旅程主线：**部门空间创建与维护 → 成员权限分配 → 文档归类与治理 → 异常与合规处理**。

| 阶段 | 用户行为 | 系统 / 平台功能 | 用户目标 | 情绪 / 痛点 |
| --- | --- | --- | --- | --- |
| **① 空间管理** | 创建 / 配置本部门空间，设定空间属性 | 部门空间管理、空间配置 | 理清部门的文档归属边界 | 无法划分边界、目录混乱 |
| **② 权限分配** | 为成员分配 查看者 / 编辑者 / 管理员 角色 | 角色权限分配、成员管理 | 让合适的人访问合适的内容 | 误授权、权限继承不清晰 |
| **③ 文档治理** | 归类移动文档、清理冗余、统一命名 | 移动 / 归档 / 删除、批量操作 | 保持空间整洁、可检索 | 冗余文件堆积、无治理工具 |
| **④ 异常处置** | 处理成员权限申请、越权访问等异常 | 权限回收、访问记录查看 | 及时收回不当权限 | 处置无依据、过程难追踪 |
| **⑤ 合规背书** | 核对敏感 / 机密文档的访问权限 | 权限核对、审计留痕 | 证明权限合规、可审计 | 无法快速自证合规 |

---

### 2.3 超级管理员（IT/行政）—— 系统配置、存储配额与安全审计

旅程主线：**系统初始化与配置 → 存储 / 配额管理 → 全局审计监控 → 告警与整改**。

| 阶段 | 用户行为 | 系统 / 平台功能 | 用户目标 | 情绪 / 痛点 |
| --- | --- | --- | --- | --- |
| **① 系统配置** | 完成系统初始化、基础参数与全局角色配置 | 系统配置、全局参数、角色策略 | 让系统以正确策略上线 | 配置零散、无全局视角 |
| **② 存储配额** | 设定部门 / 全局存储配额并监控用量 | 存储配额管理、用量统计 | 合理分配并避免资源浪费 | 配额失控、无法预警 |
| **③ 安全审计** | 查看登录、访问、操作、合成等审计日志 | 审计日志、操作留痕、访问记录 | 掌握系统安全全貌 | 无日志、异常难发现 |
| **④ 告警处置** | 定位异常行为（越权、异常大量操作）并整改 | 告警提示、异常定位 | 及时阻断风险 | 告警误报、处置低效 |

## 3. 核心原子化用户故事（INVEST 原则）

> 所有用户故事均遵循 **INVEST**（Independent 独立 / Negotiable 可协商 / Valuable 有价值 / Estimatable 可估算 / Small 足够小 / Testable 可测试）原则，采用标准三段式 **“As a … I want to … So that …”** 表述。
>
> 优先级说明：P0 = MVP 必须（构成“上传→检索→合成→确认→归档”闭环与权限/配额/审计的底座）；P1 = MVP 重要；P2 = 后续增强。

### 3.1 普通员工 —— 文档生命周期闭环

| 编号 | 优先级 | 用户故事 |
| --- | --- | --- |
| US-EMP-01 | P0 | As a 普通员工, I want to 上传文档到本部门空间 So that 我的文档能被安全存储并由合适的人访问。 |
| US-EMP-02 | P0 | As a 普通员工, I want to 在线查看 / 预览我有权限访问的文档 So that 无需下载即可快速了解文档内容。 |
| US-EMP-03 | P0 | As a 普通员工, I want to 用自然语言查询并语义检索部门内文档 So that 即使不记得关键词也能快速定位相关内容。 |
| US-EMP-04 | P0 | As a 普通员工, I want to 检索结果清晰展示匹配文档及引用来源 So that 我能判断检索结果的可靠性与相关性。 |
| US-EMP-05 | P0 | As a 普通员工, I want to 基于选定的检索结果发起 AI 合成（周报汇总 / 方案初稿 / 制度摘要） So that 快速生成结构化的新文档初稿。 |
| US-EMP-06 | P0 | As a 普通员工, I want to 在 AI 生成期间看到明确的进度提示 So that 我能知晓合成正在进行而不会误以为系统卡死。 |
| US-EMP-07 | P0 | As a 普通员工, I want to AI 合成结果中标明每个观点的引用来源 So that 我能核实内容可信度并保证可溯源。 |
| US-EMP-08 | P0 | As a 普通员工, I want to 人工审阅并编辑确认 AI 合成结果后再提交 So that 避免不可信内容未经确认而直接入库存档。 |
| US-EMP-09 | P0 | As a 普通员工, I want to 将确认后的新文档归档到指定目录并继承权限 So that 产出能够持久沉淀并被他人复用。 |
| US-EMP-10 | P1 | As a 普通员工, I want to 查看文档的历史版本并追溯变更记录 So that 我能了解文档演进并还原误修改。 |
| US-EMP-11 | P2 | As a 普通员工, I want to 收藏 / 星标常用文档 So that 我能快速访问高频使用的内容。 |

## 4. MVP 闭环校验（Traceability）

以下为 MVP 必须打通的**最小闭环链路**，用于验证产品可用性：

```
上传/查看 ──▶ 语义检索(map→引用来源) ──▶ AI合成(带进度+来源标注)
      ▲                                          │
      │                                          ▼
 归档沉淀 ──◀── 人工确认+编辑 ◀──────────────────────┐
             (确认后方可入库, 来源可溯源)
```

**MVP 验收底线**
1. 普通员工可在部门空间内完整走通“上传→检索→合成→确认→归档”闭环；
2. AI 合成结果的每个关键观点可追溯到源文档；未经人工确认不得自动入库；
3. 部门管理员可完成角色分配与基本治理；超级管理员可完成配置、配额与审计；
4. 不涉及全文搜索引擎、实时协同编辑、审批流与跨组织外部分享。

## 5. 后续迭代建议（Out of MVP）

以下能力已超出 MVP 极简边界，建议作为后续迭代储备：

- 全文搜索引擎（当文档规模扩大时引入）
- 在线多人实时协同编辑（OT / CRDT）
- 文档审批流
- 跨组织外部分享
- 高级检索（组合筛选、检索历史与收藏）
- 智能分类 / 标签自动打标
