# DocHub —— BDD 验收标准清单（User Stories & Acceptance Criteria）

> 文档版本：v1.0
> 依附文档：docs/01-requirements/用户旅程与原子故事分解.md
> 编写规范：本清单针对上一步提炼的 **全部 23 条用户故事**，逐条使用标准 **Given-When-Then（BDD 行为驱动）**格式编写断言。
> 覆盖要求：每条故事包含 **1 条主干正常流（Happy Path）** + **至少 2 条异常边界流（Edge Cases）**，语言精准、可判定，可直接转化为自动化测试用例。

---

## 0. 通用边界前提（跨故事共享上下文）

以下边界作为多条故事共享的前置约束，后续场景若未特殊说明则默认成立：

- **权限模型**：角色为 查看者 / 编辑者 / 管理员；查看者可读不可写，编辑者可选读可写，管理员可读写并管理空间。
- **权限判定时机**：所有读 / 写 / 检索 / 下载操作均在服务端二次校验，不可仅依赖前端隐藏。
- **来源校验（检索 / 合成）**：AI 合成引用的每个观点必须能映射到一条真实存在于当前部门空间且当前用户有权限访问的源文档。
- **入库存档前提**：AI 合成结果必须同时满足 (a) 通过来源溯源校验 且 (b) 用户显式人工确认，缺一不可，否则禁止入库。

## 1. 普通员工 —— 文档生命周期闭环

### US-EMP-01：上传文档到本部门空间

**Happy Path：正常上传**
```
Given 我是一个已登录的普通员工
And 我属于"研发部"部门空间
And 我拥有该空间的"编辑者"角色
And 该空间当前存储用量未超过配额
When 我上传一个支持格式的文档"设计规范V1.pdf"
Then 系统返回上传成功
And 文档"设计规范V1.pdf"出现在研发部空间的文档列表中
And 其他拥有该空间查看权限的成员可见该文档
```

**Edge Case 1：无权限用户被拦截（上传位置越权）**
```
Given 我是一个已登录的"市场部"普通员工（查看者）
And 我尝试上传文档到我不属于的"研发部"空间
When 我调用上传接口
Then 系统返回 HTTP 403 权限拒绝
And 不产生任何存储 / 元数据写入
And 无任何用户可见该次操作产生的文档
```

**Edge Case 2：配额超限禁止上传**
```
Given 研发部空间当前存储用量已达配额上限（100%）
And 我是一个拥有该空间"编辑者"角色的员工
When 我上传任意文档
Then 系统返回"存储配额已满，禁止上传"的错误提示
And 上传请求被拒绝，文档不落地
```

**Edge Case 3：同名文件产生版本冲突**
```
Given 研发部空间已存在文档"设计规范V1.pdf"
And 其版本号为 v1
When 我再次上传同名文档"设计规范V1.pdf"
Then 系统不覆盖原文件
And 系统生成新版本 v2 并保留原 v1 文档内容
And 版本记录中同时存在 v1 与 v2
```

### US-EMP-02：在线查看 / 预览有权限的文档

**Happy Path：正常在线预览**
```
Given 我是一个已登录的普通员工
And 我拥有文档"周报模板.xlsx"所在空间的查看权限
When 我在文档列表点击"预览"
Then 系统在浏览器内渲染该文档内容
And 页面显示文件类型、大小与最后修改时间
```

**Edge Case 1：无权限用户被拦截（预览拦截）**
```
Given 我是一个已登录的"销售部"员工
And "财务预算.xlsx"属于我不具备任何权限的"财务部"空间
When 我尝试访问该文档的预览地址
Then 系统返回 HTTP 403 权限拒绝
And 不返回文档任何内容（不泄露文件名外的元数据）
```

**Edge Case 2：无权限下载被拦截**
```
Given 我仅拥有文档"会议纪要.md"的"查看者"角色
When 我尝试下载该文档原始文件
Then 系统返回 HTTP 403 权限拒绝
And 不产生任何下载流量或临时文件
```

**Edge Case 3：不支持的格式给出明确反馈**
```
Given 我拥有文档"工程图.abc"的查看权限
And 系统不支持该扩展名的在线预览
When 我点击"预览"
Then 系统显示"暂不支持在线预览，请下载后查看"的明确提示
And 提供可用的替代动作（下载 / 复制路径）
```

### US-EMP-03：自然语言语义检索部门内文档

**Happy Path：自然语言检索命中**
```
Given 我是一个已登录的研发部员工
And 研发部空间内存在与"芯片选型"相关的多个文档
When 我用自然语言查询"我们去年对芯片选型做了哪些分析"
Then 系统返回排序后的相关文档列表
And 每条结果包含文档标题、匹配摘要与相关性评分
And 列表仅包含我拥有访问权限的文档
```

**Edge Case 1：越权检索不到受限文档**
```
Given 我是一个"市场部"员工
And "研发部"空间包含文档"年度薪酬表.pdf"
And 我对该文档 / 其空间无任何访问权限
When 我用关键词"薪酬表"执行语义检索
Then 检索结果中不出现"年度薪酬表.pdf"
And 系统不泄露该文档存在与否的任何信息
```

**Edge Case 2：检索返回空结果**
```
Given 研发部空间内不存在任何与"量子超导引擎"相关的文档
When 我用自然语言查询"关于量子超导引擎的资料"
Then 系统返回空结果
And 显示友好提示"未检索到相关文档"
And 提示用户调整措辞或检查检索范围
```

**Edge Case 3：输入为空 / 过短**
```
Given 我在检索框中未输入任何内容或仅输入空白字符
When 我触发检索
Then 系统不发起任意索引查询
And 给出"请输入检索内容"的校验提示
```

### US-EMP-04：检索结果展示引用来源

**Happy Path：结果带来源信息**
```
Given 我已完成一次语义检索并得到结果集合
When 系统返回检索结果列表
Then 每条结果均展示来源文档标题、作者、更新时间与所属空间
And 显示该片段在该文档中的命中位置（如章节 / 页码）
```

**Edge Case 1：来源文档随后失去访问权限**
```
Given 我检索"季度销售数据"
When 检索结果中某文档的来源随后被移除我的访问权限
And 我点击该结果尝试查看
Then 系统返回 HTTP 403 或被标记为"已失去访问权限"
And 结果列表中该条被即时标记，避免误导
```

**Edge Case 2：来源元数据缺失**
```
Given 系统返回某条检索结果
When 该来源文档的作者 / 更新时间字段为空
Then 结果展示"未知"占位而非为空或报错
And 仍展示可用的标题与所属空间，不影响点击查看
```

### US-EMP-05：基于检索结果发起 AI 合成

**Happy Path：正常发起合成**
```
Given 我已完成检索并选中了 5 篇相关文档作为引用来源
And 我选择合成类型为"周报汇总"
When 我点击"生成"
Then 系统创建一次 AI 合成任务并在待办中登记
And 系统返回任务状态为"生成中"
```

**Edge Case 1：未选择任何来源发起合成**
```
Given 我未勾选任何检索结果文档
When 我点击"生成"
Then 系统禁止发起合成
And 提示"请至少选择一篇引用来源文档"
```

**Edge Case 2：所选来源全部越权 / 失效**
```
Given 我勾选了 3 篇文档作为来源
And 其中 2 篇在发起时已失去我的访问权限
And 我点击"生成"
Then 系统在任务创建时进行来源可用性校验
And 返回"部分或全部引用来源无访问权限，生成已终止"
And 不创建合成任务
```

**Edge Case 3：合成类型无效**
```
Given 我发起合成时提交了不在枚举范围内的合成类型（如空值 / 未知值）
When 请求发送到服务端
Then 系统返回参数校验错误
And 合成任务不被创建
```

### US-EMP-06：AI 生成期间展示进度提示

**Happy Path：展示明确进度**
```
Given 我已成功发起一次 AI 合成任务，任务状态为"生成中"
When 系统处理该任务
Then 前端持续展示进度状态（如"正在检索"→"正在汇总"→"正在起草"）
And 页面显示加载指示器，不发生页面假死
And 任务完成后自动切换为"已完成"
```

**Edge Case 1：用户切换页面不中断任务**
```
Given 我有一个正在生成中的 AI 合成任务
When 我离开当前页面导航到其他模块
Then 该生成任务在后台继续执行，不被取消
And 任务完成状态在全局待办中可见
```

**Edge Case 2：任务异常中断有明确反馈**
```
Given 我的 AI 合成任务在处理中
And 后端返回超时 / 服务异常错误
When 任务失败
Then 状态置为"失败"并展示错误原因
And 提供"重试"操作
```

### US-EMP-07：AI 合成结果标注引用来源

**Happy Path：观点可溯源**
```
Given 我已获得一份 AI 合成结果"研发季度周报"
When 我查看该文档内容
Then 文档中的每个关键观点均附有来源标注
And 每个标注可点击跳转到具体源文档及命中片段
```

**Edge Case 1：无来源支撑的观点被标记**
```
Given AI 合成的部分内容无法映射到任何源文档
When 系统渲染合成结果
Then 该部分被明确标记为"无引用来源 / 需人工核实"
And 标记不能被静默忽略，用户必须确认后才能继续
```

**Edge Case 2：来源引用中断无从追溯**
```
Given 某个观点标注了来源文档 A
When 用户点击该来源标注
And 文档 A 已不存在或被清除
Then 系统显示"来源文档已失效"提示
And 该来源被标记为不可验证
```

### US-EMP-08：人工审阅并确认后才入库

**Happy Path：确认方可入库**
```
Given 我获得一份已通过来源校验的 AI 合成结果
When 我审阅并点击"确认入库"
And 系统再次执行来源溯源校验通过
Then 文档被写入指定目录
And 返回成功状态并在文档列表可见
```

**Edge Case 1：未经人工确认禁止入库**
```
Given 我获得一份 AI 合成结果
And 我未执行任何显示确认动作
When 系统或后台尝试自动入库归档
Then 入库动作被拒绝
And 文档保持"草稿 / 待确认"状态，不进入正式文档列表
```

**Edge Case 2：存在无来源标记时禁止确认**
```
Given 合成结果中存在被标记为"无引用来源"的段落
And 我尝试点击"确认入库"
Then 系统禁止入库
And 提示"存在无来源支撑的内容，请先补充来源或删除该内容"
```

**Edge Case 3：确认后校验失败回滚**
```
Given 我点击"确认入库"
And 系统中某源文档同时被删除导致来源校验失败
When 进行最终溯源校验
Then 入库被终止
And 文档停留在草稿状态，不产生部分落库数据
```

---

### US-EMP-09：归档指定目录并继承权限

**Happy Path：正常归档并继承权限**
```
Given 我已有一份经确认入库的文档
And 我选择归档到研发部空间下的"项目复盘"目录
When 我执行归档
Then 该文档移动到目标目录
And 其访问权限继承目标目录 / 空间的权限设置
```

**Edge Case 1：目标目录无访问权限**
```
Given 我选择归档到我不具写入权限的目标目录
When 我执行归档
Then 系统返回 HTTP 403 权限拒绝
And 文档保持原位置不变
```

**Edge Case 2：归档后权限被回收**
```
Given 文档 D 经我确认后归档到目录 X
And 随后管理员移除了我对目录 X 的写入权限
When 我再次尝试移动 / 覆盖该文档
Then 系统返回 HTTP 403 权限拒绝
And 我仍可保留读权限（如角色未变更）则不影响查看
```

**Edge Case 3：目标目录不存在**
```
Given 我选择的归档目标目录已被删除
When 我执行归档
Then 系统返回"目标目录不存在"错误
And 文档不被移动
```

### US-EMP-10：查看历史版本并追溯

**Happy Path：查看版本历史**
```
Given 文档"设计规范V1.pdf"存在版本 v1、v2、v3
And 我拥有该文档查看权限
When 我点击"版本历史"
Then 系统按时间倒序列出版本号、修改人、修改时间
And 我能选中任一版本预览其内容
```

**Edge Case 1：无权限用户查看版本**
```
Given 我没有文档"设计规范V1.pdf"的访问权限
When 我尝试访问其版本历史接口
Then 系统返回 HTTP 403 权限拒绝
And 不返回任何版本元数据
```

**Edge Case 2：版本缺失或损坏**
```
Given 文档的历史版本列表中某版本 v2 已被后台清除
When 我点击预览 v2
Then 系统显示"该版本不可用"提示
And 不影响 v1 与 v3 的正常查看
```

**Edge Case 3：同名上传生成新版本**
```
Given 我以编辑者身份再次上传同名文档
When 系统处理该上传
Then 生成新的递增版本号且不覆盖历史版本
And 版本历史新增一条记录
```

Then 系统返回 HTTP 403 权限拒绝

**Edge Case 2：重复收藏**
```
Given 我已收藏文档"运维手册.md"

Then 系统不产生重复收藏记录

When 我浏览我的收藏列表
Then 该文档从收藏列表中隐藏或被标记为"无权限"
And 不触发报错
```

## 2. 部门文档管理员 —— 权限分配与文档治理

### US-DMA-01：创建并配置部门空间

**Happy Path：创建部门空间**
```
Given 我是一个已登录的部门文档管理员
And 我是"研发部"的管理员
When 我创建一个名为"研发部"的部门空间并设置空间配额 100GB
Then 系统创建空间成功
And 我自动成为该空间的管理员
And 空间初始配置（配额、默认角色）被保存
```

**Edge Case 1：空间名称重复**
```
Given 系统中已存在名为"研发部"的部门空间
When 我再次创建同名空间
Then 系统返回"空间名称已存在"错误
And 不创建新空间
```

**Edge Case 2：配额设置非法**
```
Given 我尝试将空间配额设置为 0 或负数
When 我提交空间配置
Then 系统返回参数校验错误
And 空间不被创建
```

**Edge Case 3：非管理员用户创建空间**
```
Given 我是一个仅拥有"查看者"角色的成员
When 我调用创建部门空间的接口
Then 系统返回 HTTP 403 权限拒绝
And 不创建任何空间
```

---

### US-DMA-02：为成员分配角色

**Happy Path：正常分配角色**
```
Given 我是研发部空间的管理员
And 成员"张三"属于研发部
And 目标文档 / 空间允许分配
When 我为"张三"分配"编辑者"角色
Then 权限保存成功
And 张三立即获得"编辑者"对应权限
```

**Edge Case 1：无权分配更高角色**
```
Given 我是一个拥有研发部"编辑者"角色（而非管理员）的用户
When 我尝试将成员升级为"管理员"
Then 系统返回 HTTP 403 权限拒绝
And 成员角色保持不变
```

**Edge Case 2：把成员降级移除后原权限失效**
```
Given 成员"张三"原为研发部"编辑者"
When 管理员将其角色改为"查看者"
Then 张三的写权限立即失效
And 张三再尝试编辑文档返回 HTTP 403
```

**Edge Case 3：分配不存在的成员 / 角色**
```
Given 我尝试为不存在的用户"李四"分配角色
Or 我尝试分配不存在的角色"超级编辑"
When 我提交分配请求
Then 系统返回参数 / 引用校验错误
And 操作失败且不产生部分保存
```

### US-DMA-03：查看成员权限与角色明细

**Happy Path：查看权限明细**
```
Given 我是研发部空间管理员
When 我打开"成员管理"
Then 系统展示研发部全部成员列表
And 每位成员展示其角色与权限范围
```

**Edge Case 1：无权限用户查看成员列表**
```
Given 我是一个普通查看者成员
When 我调用成员权限查询接口
Then 系统返回 HTTP 403 权限拒绝
And 不返回任何成员权限数据
```

**Edge Case 2：数据为空 / 不一致**
```
Given 某成员被标记为存在但权限记录缺失
When 我刷新成员权限明细
Then 系统以"未分配角色"占位展示而非异常崩溃
And 指出需管理员补全该成员权限
```

### US-DMA-04：文档移动 / 归类 / 统一命名

**Happy Path：正常移动文档**
```
Given 我是研发部空间管理员
And 我对目标目录具有写入权限
When 我将文档"旧方案.docx"移动到目录"项目A"
Then 文档移动成功且出现在目标目录
And 原目录不再保留该文档记录
```

**Edge Case 1：移动目标无写权限**
```
Given 目标目录属于我无写入权限的空间
When 我执行移动
Then 系统返回 HTTP 403 权限拒绝
And 文档保持原目录不动
```

**Edge Case 2：移动后权限随之改变**

And 目标目录仅有"查看"权限层级
When 移动完成后我尝试再次编辑该文档
Then 系统按目标目录权限返回 HTTP 403
And 移动过程产生审计记录

**Edge Case 3：目标目录已满 / 重名冲突**
```
Given 目标目录已存在同名文档"旧方案.docx"

And 未确认前不覆盖目标文件
```

以下为本次迭代中用户特别强调、且跨多个故事生效的**核心安全 / 治理边界**，已在上述场景中落点：

| --- | --- | --- |

## 5. 可测试性说明（Mapping to Automation）

- **状态码约定**：所有权限拒绝断言统一为 `HTTP 403`；参数非法统一为 `HTTP 400 / 422`；成功统一为 `HTTP 200/201` 且伴随可断言的业务状态字段。
- **场景与用例映射**：每条 Given-When-Then 可直接映射为一条自动化测试用例（如 Cucumber Feature / JUnit+AssertJ / 接口测试脚本）。
- **数据隔离**：测试夹具必须预置独立的部门、成员与文档资源，避免测试间相互污染权限与配额状态。
- **幂等约束**：涉及回收 / 处置 / 收藏等重复操作，断言结果幂等。
